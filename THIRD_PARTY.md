# Reference provenance

The protocol research and generated Huffman/entity-schema data use [JACoders/OpenJK](https://github.com/JACoders/OpenJK) at revision `1a6a643427aa347553e9073dac5570b33337c4d9`. OpenJK's source is licensed under GNU GPL version 2 and carries notices for id Software, Raven Software, Activision, ioquake3 contributors and OpenJK contributors.

The reference-fetch script retrieves `LICENSE.txt` alongside source into `.references/OpenJK/<revision>/`. The isolated protocol C++ test harness compiles that reference code separately from the Rust application. Generated tables and conformance fixtures identify their source revision and include a source-hash manifest. They are derived from the reference, not claimed as clean-room artifacts.

The offline movement milestone also **links original OpenJK native code into the client** through `jka-movement`: multiplayer Pmove, slide movement, animation/saber movement helpers, shared math and original compiled-BSP brush/patch collision. The byte-identical source closure, GPL-2.0 license and SHA-256 manifest are under `crates/jka-movement/vendor/openjk`, at the same pinned revision above. `scripts/vendor-movement.py --check` verifies the vendored files. `build.rs` lists compiled translation units; the included server files `w_force.c`, `g_client.c`, `g_active.c` and `g_xcvar.h` serve as references for the offline host and are not compiled. The host/adapters are separate files in `crates/jka-movement/native`. This crate is declared GPL-2.0-only; it is not a clean-room implementation. No proprietary game animations, maps, textures or models are bundled.

JAPRO prediction also links the shared C gameplay code from [taysta/TaystJK](https://github.com/taysta/TaystJK/tree/b35ed06fec41c53644352743c6b199a5d5d500f3), revision `b35ed06fec41c53644352743c6b199a5d5d500f3`. The byte-identical sources, GPL-2.0 license, and SHA-256 manifest are under `crates/jka-movement/vendor/japro`. Verify them with `python scripts/vendor-movement.py --japro --check`. Native symbol prefixes isolate this backend from stock OpenJK. The separate host adapters and the C collision-filter adaptation from `cg_predict.c` live in `crates/jka-movement/native`; physics has not been translated into Rust. See [MOD_SUPPORT.md](crates/jka-movement/MOD_SUPPORT.md) for scope and validation limits.

The `japro-web`, local jaPRO and OpenJK WASM working trees are additional research references. Original demos remain in the user's game installation; only hashes and comparison results are stored here.

The native RBSP importer uses the format declarations in the local OpenJK WASM `codemp/qcommon/qfiles.h` and patch index ordering in `codemp/rd-vanilla/tr_surface.cpp` as references. `japro-web/viewer/lib/bspLoader.js` informed the format audit. Source hashes and importer limits are recorded in `Development Docs/Map validation.md`. The fixed quadratic patch evaluator is native Rust, not a port of OpenJK's adaptive subdivision/collision code. User-owned BSP content is extracted only into ignored `target/dev-assets` and is not a distributable fixture.

The graphical application uses native winit and wgpu rendering with egui for its interface; it does not depend on Bevy. PK3 reading uses zip 8.6.0 (MIT). Dependency versions are recorded in Cargo.lock. Bevy was consulted during earlier renderer research but is not part of the application or runtime. The runtime reads user-supplied PK3s in place; no game content is bundled in the executable.

The sky occlusion investigation consulted japro-web commit `8d5d4cf4829b6fdb0e8b65a96afa8ce9657a0642` (`sky fix`) and `viewer/viewerMap.js`. Its depth-writing, color-disabled sky geometry informed the native wgpu depth-prepass and material implementation. Stock user-owned `.shader` declarations are parsed at runtime by the initial Rust material interpreter. No JavaScript renderer code or proprietary textures are bundled. `qbsp` and `bevy_trenchbroom` were reviewed as references; neither is a dependency of this build.

The later surface-classification correction uses JKA constants from local OpenJK `codemp/game/surfaceflags.h`: sky `0x2000`, nodraw `0x200000`, material-ID mask `0x1f`. The earlier Quake 3 flag assumptions were incompatible with JKA. japro-web commits `6f61145` and `282acd8` were inspected for the opaque multiply-blend rule and player-model culling distinction. Earlier Bevy render-to-texture, SSAO and custom-material examples were research references for the native rendering controls and reflection integration; the mirror uses a native reflected-camera/projective-sampling implementation with reverse-Z oblique clipping.
